Rationale for generating rather than parsing at runtime: `contracts/` sits at the workspace root,
OUTSIDE `crates/aprender-core/`, so a packaged crate cannot read it and `cargo package --verify`
would fail. D-14's property (a tolerance change requires a visible, `pv diff`-flagged contract edit)
is preserved because (a) the generated file is derived, never hand-edited, and (b) the agreement
test below fails the build if the two ever diverge in a workspace checkout.

Agreement test (in tests/setfit_conformance.rs): locate
`contracts/setfit-encoder-conformance-v1.yaml` by walking up from CARGO_MANIFEST_DIR. If found
(every dev and CI run), parse it and assert every generated constant equals the contract value AND
that the file's sha256 equals `CONTRACT_SHA256`. If NOT found (packaged-crate context only), assert
`CONTRACT_SHA256` is a well-formed 64-hex string and pass — documented as the only skip in the suite.

Fixture schema: see 01-04 PLAN interfaces block (field names are frozen there).
AdamW: impl lives in nn/optim/rm_sprop.rs (struct declared nn/optim/mod.rs:391).
`AdamW::new(params, lr)` defaults betas (0.9, 0.999), eps 1e-8, weight_decay 0.01
(rm_sprop.rs:10-24); builder `.betas(b1,b2).eps(e).weight_decay(wd)`;
`step_with_params(&mut [&mut Tensor])` (rm_sprop.rs:87). Decay is DECOUPLED:
`param -= lr * wd * param` applied before the Adam update (rm_sprop.rs:80) — same ordering as
torch AdamW's `p.mul_(1 - lr*wd)`. Do NOT rely on these defaults in the gate: configure every
hyperparam explicitly from optimizer_step.json (defaults can drift; the fixture is the arbiter).
NOTE: the plain `Adam` struct in nn/optim/mod.rs uses COUPLED L2 decay and defaults wd 0.0 —
wrong optimizer for this gate; use `AdamW`.

**ENC-04 gate semantics (canonical, used by gradient_gate.rs and detach_negative.rs):**
- every named trainable tensor: gradient exists, all elements finite;
- every contracted component (embeddings; per-layer attention; per-layer FFN; per-layer norm):
  aggregate gradient L2 norm > 0;
- per-tensor non-zero required only for names ABSENT from `gradients.json.analytically_zero`;
- names PRESENT in that list must satisfy `max|g| <= ZERO_GRAD_FLOOR` — the exemption is two-sided,
  so an unexpectedly large key-bias gradient is a failure, not a pass.
