<objective>
Create the method-neutral decision crate `aprender-decide` (D-14) with its `DecisionMethod` seam, the
D-05 task parser, and Laya as the first and only method — head, scorer, request builder and
temperature buckets on top of core's ModernBERT — proven against the tiny Laya oracle in CI.

Purpose: the decision layer is not an encoder concern (D-13 keeps the encoder generic), and it must
host Kev/Jev later without reshaping the artifact or tool contract — but only one implementation is
built now. The task parser is where D-05's "order is the label index" is won or lost (Pitfall 2).

Output: `crates/aprender-decide/{Cargo.toml,README.md,src/lib.rs,src/task.rs,src/laya/*.rs}`, the
workspace member, the README crate count.

Recorded note on D-05: the decision text names `serde_json` `preserve_order` (spike 026's mechanism).
The substance — criteria order is the label index — is implemented with an order-preserving
`MapAccess` visitor over the raw bytes instead of enabling the feature on this crate, because the
feature is unified workspace-wide by pmcp and enabling it here would silently change other crates'
map behaviour in any build that includes this one (Pitfall 2; STATE records two such incidents). The
visitor gives the same order under both backings, which the dual-shape test proves.
</objective>

once), `fn classify_prepared(&self, rows: &[PreparedRow]) -> Result<Vec<Decision>, DecideError>`, and
a provided `fn classify(&self, texts: &[String])`. `Decision { label_index: usize, probabilities: Vec<f32>,

`Display`; no `unwrap()` anywhere (use `ok_or_else(..)?`, the spike code is not lint-clean).

`src/task.rs` (per D-05): `Task { instructions, criteria: Vec<Criterion { name, description: Option<String> }> }`
and `Task::from_slice(bytes)`: deserialize a `#[serde(deny_unknown_fields)]` document whose `criteria`
field uses an `OrderedCriteria` newtype with a hand-written `Visitor::visit_map` that pushes
`(key, Option<String>)` pairs in document order and refuses a duplicate key — reading from the raw
bytes with `serde_json::from_slice`, NEVER via `serde_json::Value`/`Map` (Pitfall 2). Refusals as typed
`TaskError`: `type` other than `"choice"`, fewer than 2 criteria, duplicate criterion, empty name.
