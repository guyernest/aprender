write the deploy recipes — bucket, content-addressed upload, config generation, fail-closed deploy with

refuse an ungated artifact.

mechanism, per the decision). Nothing touches AWS in this plan — the live run is plan 08-11, behind its
own checkpoint.

Recorded choice (Claude's discretion: S3 layout, IAM scoping): the weights bucket is created by an
idempotent aws-cli recipe rather than a new CDK stack in `deploy-extensions/`, because
`deploy-extensions/bin/app.ts` refuses to synthesize without the SetFit trainer asset, so a decide
stack in that app would couple the weights bucket to an unrelated build; and it is not a prefix in the
SetFit training bucket, whose dev posture destroys data by design. The grant follows the
`pmcp-train-grant` precedent (role discovered from the function, inline policy, re-run after any
pmcp.run redeploy).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| laptop -> AWS account (S3, IAM, Lambda) | recipes create resources and grants |
| laptop -> external SDK repo | patch option modifies and installs a tool from another repository |
| pmcp.run -> deployed function | the platform owns the role and stack; our grant is out-of-band |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-10-01 | Spoofing | wrong binary deployed under the decide name | high | mitigate | Human-chosen resolution fix + compile-log assertion + live identity probe (artifact_sha256 and labels) |
| T-08-10-02 | Elevation of privilege | over-broad S3 grant | high | mitigate | Inline policy limited to GetObject on decide/<server>/* and prefix-conditioned ListBucket; no write |
| T-08-10-03 | Tampering | ungated or swapped artifact deployed | high | mitigate | gate_policy_ok from the Rust inspector, sha256 pin in config, head-object size check, selftest proves each refusal |
| T-08-10-04 | Information disclosure | public bucket / account id in git | medium | mitigate | Public access blocked, SSE-S3, generated config gitignored, template placeholders only |
| T-08-10-05 | Tampering | locally built cargo-pmcp | medium | mitigate | Commit SHA + version asserted by the recipe; unit test in the SDK; upstream PR for review |
| T-08-10-06 | Repudiation | status read through a pipe | medium | mitigate | cargo pmcp status captured directly, log written separately (CLAUDE.md Verification #1) |
</threat_model>
