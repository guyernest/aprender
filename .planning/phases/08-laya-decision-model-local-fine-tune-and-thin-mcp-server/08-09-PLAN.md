probabilities; the gated full-model test reproduces spike 025's 14-row fixture; and the stance demo

the fine-tuned checkpoint, which CI cannot hold. Enforcing the gate again in Rust means a hand-edited
or stale gate-report.json cannot be packed.

variant: `pass == false` (`GateFailed`), report thresholds not equal to the contract's
(`ThresholdMismatch { field, report, contract }`), a recomputed pass
(`ft.macro_f1 - zs.macro_f1 >= margin && ece_post <= max_ece`, NaN-visible comparisons) that
disagrees with the reported `pass` (`PassDisagrees`), and non-finite metrics. Add
`rescore(decider, eval_rows, eval_probs, tolerance) -> Result<RescoreReport, PackPolicyError>`:
verify each eval row's text sha256 equals the `eval-probs.json` entry for its index, classify every
row through `decider.prepare` + `classify_prepared` (the loaded model, not the inputs), and compute
max |dp| over all rows and labels plus argmax agreement; refuse (`RescoreDrift { row, max_abs }` /
`ArgmaxDrift { row }`) when |dp| exceeds the tolerance (NaN-visible) or any argmax differs. Unit tests
with fabricated reports and a tiny Decider (from the laya_tiny fixture) cover every variant.

`examples/pack_laya.rs` (serde_yaml and sha2 are dev-dependencies available to examples):
`pack --run <dir> --data <dir> --out <file>` — (1) read thresholds from
`contracts/laya-finetune-gate-v1.yaml` and `pack_rescore_probs_abs` from `contracts/laya-parity-v1.yaml`
at run time (repo-relative to the workspace root); (2) parse `gate-report.json` and
`check_gate_report`; (3) verify the data dir's `task.json`/`train.jsonl`/`eval.jsonl` sha256 equal the
report's `inputs_sha256` and `eval-probs.json` equals `eval_probs_sha256`; (4) `pack_run_dir`;
(5) `Decider::load_bytes` on the packed bytes (full ladder, probes included); (6) `rescore` all eval
rows; (7) only then write the file atomically (temp file in the same directory + rename) and print

nothing. `inspect <file>` runs `inspect_manifest` (bounded read, header, manifest rungs only) plus

`artifact_sha256`, `recipe_id`, `method`, `base`, `labels`, `gate{pass,margin,ece_post}`,
`gate_policy_ok` (true only if `check_gate_report` accepts the embedded report), `schema_version`.
This is the single Rust-side check the deploy recipe (plan 08-10) calls — there is no second .apr
reader in bash or Python.
