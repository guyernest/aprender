<objective>
Close the torch -> .apr -> Rust chain on real weights (D-17): the pack CLI enforces the gate policy in
Rust (D-07), reloads what it packed and re-scores every eval row against Python's F16-reload
probabilities; the gated full-model test reproduces spike 025's 14-row fixture; and the stance demo
(D-19) becomes the one artifact the live deploy will serve, its sha256 being the D-11 identity.

Purpose: the tiny fixture proves the architecture in CI; this plan proves the real 0.84 GB model and
the fine-tuned checkpoint, which CI cannot hold. Enforcing the gate again in Rust — on metrics
RECOMPUTED from probabilities that are themselves verified against Rust re-scores of the artifact
and of the declared base — means a hand-edited, stale or forged gate-report.json cannot be packed
or deployed (review finding: recomputing pass from REPORTED metrics let an edited report pass, and
`inspect` never proved verified packing happened). Because the verifier is a Rust library with
tiny-fixture unit tests, CI exercises the gate, the split rules and the synthetic-variant refusal
even though CI never installs the Python training stack.

Output: `src/verify.rs` (+ `load_checkpoint_for_scoring` in `pack.rs`), `examples/pack_laya.rs`
(`pack`, `verify`, `inspect`), `tests/laya_parity.rs`, `just laya-pack` / `just laya-verify` /
`just laya-inspect`, and `models/decide/laya-stance-16.apr` (gitignored).
</objective>

- `VerifyPolicy { min_macro_f1_margin, max_ece, ece_bins, metric_recompute_abs, rescore_probs_abs }`
  (passed in; the library stays YAML-free).
- `check_variant`: `recipe.variant == "production"`, else `SyntheticNotDeployable`
  (laya-finetune-gate-v1 `synthetic_not_deployable`).
- `check_base(base_dir, recipe)`: sha256 of `<base>/model.safetensors` equals the recipe's declared
  base sha256, else `BaseMismatch`.
- `check_inputs`: the data dir's `task.json`/`train.jsonl`/`eval.jsonl` sha256 equal the report's
  `inputs_sha256`; `eval-probs.json`, `zero-shot-probs.json` and `probes.json` equal their report
  hashes; else `InputHashMismatch { file }`.
- `check_split(train_rows, eval_rows, report.calibration)`: mirror of data.py — normalized sha256
  (NFC via unicode-normalization, trimmed, internal whitespace collapsed); refuse `SplitOverlap`
  when any eval text's hash is in train, `ConflictingLabels` when one normalized train text carries
  two labels, `SliceInvalid` when `slice_ids` are unsorted/duplicated/out of range, disagree with
  `slice_size` or `slice_ids_sha256`, give a class fewer than `calibration_slice_min_per_class`
  rows, or split a normalized-text group between the slice and the fit rows.
- `validate_probs(file, eval_rows, k)`: exactly N rows, unique indices 0..N-1, each row's text
  sha256 equal to the eval row's, K finite probabilities in [0, 1] summing to 1 within 1e-5, else
  `ProbsRowCoverage` / `ProbsInvalid { row, why }` — so the aprender-core metric functions' panicking
  preconditions can never fire on file data.
- `rescore(model, eval_rows, probs, tol)`: classify every row through `prepare` + the forward (the
  fine-tuned model is the `Decider` loaded from the PACKED bytes; the zero-shot model is
  `pack::load_checkpoint_for_scoring(<base>, task)`, an in-memory `Laya` built from the base
  checkpoint through the same F16 path, never a `Decider`), compute max |dp| and argmax agreement,
  refuse `RescoreDrift { which, row, max_abs }` / `ArgmaxDrift { which, row }` beyond `tol`
  (NaN-visible).
- `recompute_metrics(probs, labels, k, ece_bins)`: macro-F1 by
  `aprender::metrics::classification::f1_score(&pred, &labels, Average::Macro)` and ECE by
  `aprender::calibration::expected_calibration_error_top_label` — the ONE Rust implementation of
  each (OPS-03), computed on the VERIFIED Python F16-reload probabilities (each already within 1e-5
  of the Rust served model, argmax exact), which is what laya-finetune-gate-v1 `f16_reload_scoring`
  defines the gate on; F_avg (stance only) is informational.
- `check_gate(report, recomputed, policy)`: report thresholds equal the contract's
  (`ThresholdMismatch`); each reported metric within `metric_recompute_abs` of its recomputation
  (`ReportedMetricMismatch { field, reported, recomputed }`); the recomputed pass
  (`ft.macro_f1 - zs.macro_f1 >= margin && ece_post <= max_ece`, NaN-visible) must be true
  (`GateFailed`) and equal the reported `pass` (`PassDisagrees`).
- `verify_run(...)` runs them in that order (cheap checks first, the two 280-row re-scores last)
  and returns `VerifyReport { artifact_sha256, rescore_max_abs, zs_rescore_max_abs, argmax_agree,
  recomputed{zs_macro_f1, ft_macro_f1, ece_post, margin}, deploy_eligible: true }`.
