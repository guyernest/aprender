`contract.py`: load `contracts/laya-finetune-gate-v1.yaml` with pyyaml and expose its constants,
recipe, base, demo and schema blocks; nothing downstream writes a threshold or recipe value as a
literal.

`data.py` (per D-05, D-06): `load_task(path)` validates the D-05 schema (type `choice`, instructions string,
criteria an object with at least 2 unique names; criteria ORDER is the label index — parse with
`json.load(object_pairs_hook=list)` so order and duplicates are both observable); `load_rows(path,
task)` requires `{text, label}` with label a criterion NAME, refusing unknown names and unknown keys;
`normalized_sha256(text)` (NFC, strip, collapse internal whitespace); `refuse_overlap(train, eval)`
refuses any eval text whose normalized hash is in train; `calibration_split(rows, fraction,
min_per_class, seed)` — stratified, seeded, at least `min_per_class` per class, returns fit rows,
calibration rows and the sha256 of the sorted calibration ids.

`prepare_stance.py` (per D-19): read the s16-seed13 selection manifest, check `label_names == [none, against,
favor]`, look up each `ordered_examples[].id` (`train:N`) in `data/tweet-eval-stance/train.jsonl`,
verify sha256(input) equals the manifest `exact_hash` (refuse on mismatch), and write
`data/decide/tweet-stance-16/task.json` (type choice, the tasks.py stance-abortion instructions and
criteria descriptions in the order none, against, favor), `train.jsonl` (`{text, label}` with the
label NAME) and `eval.jsonl` from all 280 `test.jsonl` rows. Output lands under root-anchored `/data/`
(tweet text must never be committed).

`train.py` (per D-01, D-03, D-04, D-06, D-07, D-08) — one declared seed in this task: (1) validate data (`eval.jsonl` is REQUIRED; refuse
overlap); (2) resolve the recipe from the contract (epochs 12 at <= 16 shots/class; above that
`--epochs` is required and must be in [4, 12]), write `<out>/recipe.json` with
`json.dumps(sort_keys=True, separators=(",", ":"))`, compute `recipe_id` = sha256 of those exact bytes,
print `RECIPE WRITTEN <recipe_id>` — before any model scores anything (D-04); (3) request the device
MPS -> CUDA -> CPU explicitly, load `Agent("convaiinnovations/laya", revision=<contract rev>,
expected_sha256=<contract sha>, device=<requested>)`, then record `device_used =
str(next(agent.model.parameters()).device)` and `torch.__version__` (Laya silently falls back to CPU,
so the requested device is not evidence — D-03) and print a WARNING if it is CPU; (4) split
fit/calibration with the declared seed; build training rows with `agent._encode_state` exactly as
ft_laya.py does and run the ft_laya.py loop (AdamW groups `encoder.*` vs rest, weight decay, cosine to
eta_min over `epochs * ceil(n_fit / batch)` steps, clip, `ce + (-proper_reward(softmax(z / T), onehot,
qt, mask, w_sph, w_rps)).mean() + 0.0 * act.sum()`, T = the initial bucket temperature), every value
from the contract; (5) save `<out>/checkpoint/model.safetensors` in F16 (the `temperature` buffer
stays F32) and copy `encoder/` and `tokenizer/` from the base snapshot; (6) RELOAD with
`Agent(<out>/checkpoint, device="cpu")` and `.float()` and print `SCORING START`; compute calibration
logits on the calibration rows, fit T by NLL with a bounded search in [calibration_temp_min,
calibration_temp_max], record `t_fitted`, `t_applied`, `clamp_hit` (Pitfall 6), write `t_applied`
into `rl_agent_config.json` `temperature_by_options[<choice bucket for K>]`, then reload AGAIN so the
eval probabilities come from Laya's own predict path with the saved temperature; (7) zero-shot:
the root checkpoint (same pinned revision) on `eval.jsonl` with the same task; fine-tuned: the
reloaded checkpoint on `eval.jsonl`; write `<out>/eval-probs.json` (row index, sha256 of the text,
K probabilities in criteria order — no text); (8) `gate.evaluate_gate` computes macro-F1, F_avg
(stance labels against/favor), ECE pre and post (15 bins, `metrics.ece_top_label`) and NLL, applies
the contract thresholds, and `train.py` writes `<out>/gate-report.json` in `gate_report_schema`
(including `inputs_sha256` of task/train/eval/base model/tokenizer, `eval_probs_sha256`,
`seeds.label = "single seed"`) and `<out>/task.json` (byte copy), then prints `GATE PASS` or
`GATE FAIL` and exits 0 on pass, 3 on fail. Log counts and timings only, never tweet text.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user dataset -> trainer | arbitrary JSONL/labels |
| HF Hub -> base weights | a downloaded checkpoint could be swapped |
| trainer -> gate report -> deploy | a fabricated or post-hoc-tuned report would launder a bad model |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-08-08-03 | Tampering | eval leakage into train/calibration | high | mitigate | Normalized-hash overlap refusal; calibration slice drawn only from train; disjointness self-test |
| T-08-08-04 | Information disclosure | tweet text in outputs/logs | medium | mitigate | Outputs carry text hashes only; data and runs under root-anchored gitignored /data/ and /models/; no text logging |
| T-08-08-05 | Spoofing | device claim | low | mitigate | device_used read from model parameters after the move; CPU flagged |
