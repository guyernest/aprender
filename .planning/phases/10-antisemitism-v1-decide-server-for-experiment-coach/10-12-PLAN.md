## Design Decisions Ledger

### Owner statements of 2026-10-22 (the source of D-19 and D-20)

1. The deployed MCP server, its Lambda and its endpoint must be renamed to reflect the dataset/decision (example: `aprender-mcp-decide-antisemite`), because several classifiers from different datasets must run in parallel under their own server ids. 2. The old server `aprender-mcp-decide` will be deleted by the owner from the pmcp.run admin UI; it keeps serving until the new one is verified. 3. The owner is not sure the partner project is a direct client of the classifiers (their understanding: agents call the classifiers, update counters and consult the partner project for decisions), so nothing written here asserts how any client consumes the server. 4. The owner thought the rename might be mostly a server-id change; the measurement above shows it is not only a Cargo.toml edit.

### Rejected and chosen

| Option | Verdict | Reason |
|--------|---------|--------|
| Rename the existing crate `aprender-mcp-decide-lambda` in place | rejected | smallest diff on paper, but it touches every reference to the shared crate (the contract's owner_crate rows and test commands, binding.yaml, the Makefile mapping, the ledger, the lib name), names shared code after one dataset, and a second model then needs a duplicate crate anyway |
| Keep the shared crate's bin AND add a thin crate | rejected | the register goes 9 to 10, which FALSIFY-MONO-011 reserves for a recorded CONTEXT decision, and the old crate stays a candidate for the resolver's first-bootstrap fallback |
| A symlink `<server>-lambda` pointing at the shared crate | rejected | cargo resolves the manifest through the link outside the workspace members and breaks the workspace-membership rule; fragile on every tool that canonicalises |
| A `[[bin]]` whose `path` points at another package's main.rs | rejected | compiles one file under two package identities, duplicates seven dependencies, and leaves a bin source outside its package |
| A per-model deploy root such as crates/decide-servers/ | rejected | removes the swap but breaks the flat `crates/aprender-*` layout that the registers and the readme gates enumerate |
| Thin per-server crate over a model-agnostic runtime library (CHOSEN) | chosen | the repeating unit for a second model is a Cargo.toml, a shim main and a README; the shared runtime keeps its name; the register swap is count-neutral |
| S3 artifact: server-side copy of the old object | priced, not chosen | needs a new AWS-writing recipe, its refusals and an offline proof; saves one laya-verify pass (the split of the 1473 s upload step is not recorded) and one 846,220,868-byte transfer; S3 copy within a region has no data-transfer charge and storing the object twice costs on the order of a few cents a month |
| S3 artifact: re-upload with `laya-upload` (CHOSEN) | chosen | the recipe already takes the server as an argument and its refusals have teeth; the upload needs only the AWS profile, so the pmcp.run login window opens after it |
