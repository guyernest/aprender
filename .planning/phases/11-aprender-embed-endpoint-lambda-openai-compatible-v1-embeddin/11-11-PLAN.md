The harness refuses to run (exit 2, `REFUSED checks: ...`) when the set of registered ids differs from the intake's or the count differs from `check_count`, naming the differences.
2. Transports behind one interface `send(event) -> {status, headers, body_text, error}` and `send_many(events)`: `inproc` (prepares a temporary model directory with the identity file as `embed-local-invoke` does, starts the native binary through one `mock_runtime.Session` and keeps that single process for the whole run) and `lambda` (`--function <name> --region <r> --profile <p>`: `aws lambda invoke` with the event as payload; a FunctionError, an invocation exception or a non-JSON payload is a check failure carrying the raw error class, never a pass). A `ctx` gives checks the events built in the requester's shape (the captured platform event when present, else the fixtures), the reference-vectors deliverable parsed with the requester's field names (`reference_vectors.fields`), the contract constants and request builders. The harness inserts its own directory at the front of sys.path before importing mock_runtime (a plain sibling import fails under `python3 -I`).
3. A defect catalog `DEFECTS`: named pure mutators applied to a transport response (drop usage; wrong dimension 383; status 500 on an input longer than the cap; object not list; data[].object wrong; indexes reversed; a vector scaled to non-unit norm; model not echoed; an error response without the envelope; an input echoed inside an error message; a truncation boundary off by one; base64 encoding with big-endian bytes; a missing statusCode; a body that is not a string; and any further defects the checks need), plus ENVIRONMENT mutators for checks that depend on something other than the response body (a transport that delays every reply past a check's bound, one that answers from another function name, one that strips a header). Each check lists in `FALSIFIED_BY` the defects that make it fail, and a check for which none is expressible is registered `unfalsifiable_locally` with the reason, reported by name and never approximated. `--inject <name>` wraps the transport with the mutator. `--matrix` runs every local check under every defect and clean, and prints which defects make which checks fail.
4. CLI: `--list` (ids, one per line), `--dump-quotes` (JSON id -> {title, quote, source, mode}), `--transport inproc|lambda`, `--run`, `--inject`, `--matrix`, `--out <json>`. A run prints one `PASS <id>`, `FAIL <id>: <reason>` or `SKIPPED <id> live-only` line per check and ends `LOCAL CONFORMANCE RESULT PASS <p>/<n>` (p passes out of n local checks; live-only checks are named after it; with the lambda transport the live-only checks execute and are counted, so n equals check_count) or `LOCAL CONFORMANCE RESULT FAIL <p>/<n>` with a non-zero exit. The word CONFORMANCE never appears without LOCAL in front of it.
