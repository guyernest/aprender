<objective>
Build, offline and with zero AWS calls, the measurement harness for the phase's biggest uncertainty: how long 64 inputs at the
256-token cap take on a real Graviton Lambda under no_grad, in how much memory, on which CPU generation, and how long a cold
start takes before a one-input canary is answered (R6). The harness is a standalone probe project that makes the production engine
call, the no-ingress CDK stack the endpoint will also use, the allowlist-first ingress scanner (R4's offline half), and the
owner-run recipes plus the normalizer that plan 11-04 uses.

Purpose: RESEARCH brackets the Lambda figure from about 6 s to about 50 s for 64 x 256 tokens, a 6x disagreement that decides
the batch limit, the memory tier and the timeout. One real invoke settles it, and it is cheaper to ask before any product code
exists. The tracer slice of this plan is the deploy-and-measure architecture itself: engine call -> Lambda arm64 package -> no-ingress
stack -> invoke -> evidence. The product tracer (event in, OpenAI shape out) is plan 11-06.

Output: a probe project and arm64 asset recipe, the stack and app wiring, the scanner and normalizer with case tables, six
`embed-probe-*` recipes, and a seeded Cargo.lock containment proof.
</objective>

3. `src/main.rs`, one binary named like the package. The model directory comes from the environment variable APRENDER_EMBED_MODEL_DIR (default /var/task/model). Two modes. `--local <event.json>` runs the handler once on the host and prints the response JSON on stdout (the mode the verify drives, with the real pinned weights). With no arguments it is the Lambda custom runtime: at start the model is loaded ONCE before `lambda_runtime::run`, then the sha256 of `<dir>/full_model.apr` is computed (streamed, with sha2) exactly as the endpoint will hash its model files at start (plan 11-08), so the cold number this gate measures contains the identity hashing; `load_ms`, `identity_ms` and `init_ms` (the whole start) are kept, and a load failure is KEPT as a string and returned in every response; the process never exits on it (an init-phase crash is a FunctionError). The handler takes a `serde_json::Value` and returns `Ok` for every input (a handler `Err` is a FunctionError). Event fields: `n` (inputs, default 64, clamp 1 to 256), `micro_batch` (default 8, clamp 1 to 64), `words` (default 700, clamp 1 to 20000), `tokenize_bytes` (optional; when above zero, one synthetic text of that many bytes is tokenized, the elapsed milliseconds reported as `tokenize_bytes_ms` with the `tokenize_kind` used, and no encode is done) and `tokenize_kind` (`prose`, the default, built by repeating the corpus, or `adversarial`: a text of that many bytes mixing CJK, accented and emoji characters, punctuation and symbol runs, control characters and zero-width characters, because byte-equivalent texts can exercise different tokenizer work; the timing includes the second pass the library makes to recover original_len for a cut input). The timed section is: tokenize the n texts once with the model's public `tokenize` to read `truncation()` and the attention mask (reported as `tokenize_ms`, `truncated_count` and `consumed_positions`, the sum of kept mask entries; this is a harness-only extra pass), then inside ONE `aprender::autograd::no_grad` closure on the encoding thread encode the texts in chunks of `micro_batch` with `encode_texts`, in request order (reported as `encode_ms`, which includes exactly one tokenization like the production door). Run the whole handler inside `tokio::task::spawn_blocking` in Lambda mode so the thread-local grad flag and tape belong to one blocking thread, and map a join error to an `error` body, not an Err. The response also carries: `probe` (the package name), `n`, `micro_batch`, `words`, `rows`, `dim`, `l2_norm_first_row`, `no_grad` true, `tape_len_after` (aprender::autograd::graph_tape_len after the closure), `load_ms`, `identity_ms`, `init_ms`, `apr_sha256`, `first_invocation_in_process`, `total_ms`, `cpu_part` and `cpu_implementer` (parsed by a pure function from /proc/cpuinfo text, null when absent), `vmhwm_kb` (a pure parser over /proc/self/status text, null when absent), `available_parallelism`, `rayon_threads_env` (the RAYON_NUM_THREADS value or null) and `rayon_pool_threads` (`rayon::current_num_threads()` called on the encoding thread: evidence that the pool the matrix kernels use engaged the intended width, not merely that the variable was set).
