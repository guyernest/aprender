<assumption_delta_decision>
**Detector:** `assumption-delta scan 06.1` returned `detected: true`, one signal,
`kind: chosen` ("the chosen rule (or the refusal) actually fires"). Read against the phase
scope there is also a real `pluralization`: the Prophet design matrix has had exactly two
column families since it shipped (seasonalities, holidays) and gains a third (extra
regressors), and `HolidayArg` stops being prophet-only and becomes a two-arm argument.

**The noun that is now primary:** the design column family. Its identity model today is
`prophet::Column.holiday: Option<(usize, i64)>` — a two-valued discriminator where `None`
means seasonality and `Some` means holiday. Appending regressor columns makes `None`
ambiguous: it now means seasonality OR regressor.

**Decision: `add-alongside`, deliberately, with the debt named.**

Promoting `Column.holiday` to a three-valued `ColumnKind` is the textbook move and is refused
here for two measured reasons, not for convenience:

1. It contradicts this phase's governing frame and its evidence. Spike 011 measured the
   splice as a 219-line ADDITIVE change touching nothing under `crates/`. `Column` is a `pub`
   struct with `pub` fields; replacing the discriminator changes `feature_row`'s
   `c.holiday.is_some()` filter, `predict`'s holiday roll-up selector and every construction
   site — that is a rewrite of the thing CONTEXT.md says not to rewrite.
2. It directly threatens SC2. D-19's byte-identical gate is free precisely BECAUSE regressor
   columns append and no existing index moves. A discriminator change restructures the type
   the gate's own mechanism test compares field by field.

**How the ambiguity is prevented from biting — the invariant this checkpoint asks for, and it
is load-bearing rather than ceremonial.** The spike prototype identified regressor columns by
NAME membership, which is O(R) per column and silently wrong under a name collision: a
regressor literally named `yearly_delim_1` would be summed into `extra_regressors_additive`.
This plan replaces name membership with the STRUCTURAL fact the splice guarantees — regressors
occupy the contiguous trailing index range `base_k..k` where `base_k = d.k - regs.len()`. Plan
06.1-03 additionally refuses a regressor whose name collides with any generated column name,
so the component map keys stay unambiguous too.

**What would force a later promote:** a fourth column family, or any change that lets a
regressor column occupy a non-trailing index.
</assumption_delta_decision>

      <pros>`values` length is the `ds` length plus the horizon on BOTH arms, so D-22 holds without amendment. `mode` and `prior_scale` mirror what Prophet's `add_regressor` actually takes. `standardize` as an optional boolean maps cleanly onto Prophet's auto rule, with `None` meaning auto.
