<objective>
Open the private, authenticated HTTPS ingress (D-12) — a Lambda Function URL created only after the
deployed function proved its 401 — then prove the endpoint over HTTPS twice: the conformance table
in the fixed profile (SC3) and the real pmcp-agent loop through the SDK fix branch (SC2). If the
deployed pin is still the release without the D-04 fix, this plan first re-pins to a release whose
history contains the D-04 auth-gate merge commit (D-02, release artifacts only) — and only that: the
content and alias fixes are recorded as `unreleased_at_pin` limitations when the tag lacks them (D-05:
none may gate the end-to-end turn). When no such release exists it does not stall open-endedly: it
writes a halt record and the phase closes as incomplete-awaiting-auth-release (SC1/SC3 reported not
delivered, no ingress, no fork build).

Purpose: SC1's platform turn (plan 09-10) needs an HTTPS URL the durable-agent-lambda can call with
a Bearer header; SC3 forbids that URL before the server gates. This plan is the hinge between the
two, and its precondition is the only place the phase waits on upstream's release cadence.
Output: the URL (gitignored id), the HTTPS auth table, the deployed-https conformance record, the
SDK HTTPS run record, the evidence updated to `deployed-url-401-verified`.
</objective>

Finding the release: for the AUTH PR (fix/gguf-router-auth-gate — URL in the 09-03 SUMMARY) `gh pr view <url> --repo paiml/aprender --json state,mergedAt,mergeCommit` (state MERGED), then `gh release list --repo paiml/aprender --limit 10 --json tagName,publishedAt` and `git merge-base --is-ancestor <auth mergeCommit> <tag>` for each tag after `git fetch upstream --tags` — the newest tag whose history contains the auth merge commit is the candidate (D-02: the newest that passes the conformance probe; the local release-local probe in Task 1 decides); its `.sha256` asset is the pin. Function URL recipe (plan 09-06): `just llm-endpoint-url <env> <profile>` → `URL OK (401 without key verified)`; the URL is in `deploy/llm-endpoint/.ids/url.json` (`url` key). Curl checks: `curl -s -o /dev/null -w '%{http_code}' -X POST -H 'content-type: application/json' [-H "authorization: Bearer $APR_PROBE_KEY"] --data '{"model":"x","messages":[{"role":"user","content":"Hi"}],"max_tokens":1}' "$URL/v1/chat/completions"`.

Agent loop over HTTPS (driver, variant script and SDK worktree from plan 09-12): `bash deploy/llm-endpoint/probe/agent-loop/make-variant.sh branch ~/Development/mcp/sdk/rust-mcp-sdk-wt-content-fix` (regenerates the ignored directory `deploy/llm-endpoint/.ids/agent-loop-branch/` with a real `Cargo.toml` — cargo accepts `--manifest-path` only for a file named Cargo.toml, which is why the old renamed-manifest approach could not build), then `CARGO_TARGET_DIR=<scratchpad>/agent-loop-target-branch cargo build --release --manifest-path deploy/llm-endpoint/.ids/agent-loop-branch/Cargo.toml`, then the binary (path recorded by 09-12 in its SUMMARY; the driver requires `APR_PROBE_KEY`) with `--base "$URL/v1" --model Qwen3.5-0.8B-Q4_K_M --insecure-http false --max-tokens 384 --timeout-s 300 --package "$PWD/deploy/llm-endpoint/probe/agent-loop/spike029/agent.package.json" --out <scratch>/agent-run-deployed-https.json`; `OpenAiCompatSource` requires HTTPS off-loopback unless allow_insecure_http (openai_compat.rs:86).
