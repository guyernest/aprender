Re-pin procedure (deploy/llm-endpoint/README.md §Re-pin, plan 09-04): edit pin.env (`APR_TAG`, `APR_ASSET`, `APR_TARBALL_SHA256` read from the new release's `.sha256`, `APR_PIN_PROFILE=fixed`) → `just llm-endpoint-image push=1` → `DRY_RUN=1 just llm-endpoint-deploy` → `just llm-endpoint-deploy` (update path: update-function-code to the new digest) → `just llm-endpoint-prove-401`.
Finding a release that carries the fix: `gh pr view <auth PR url> --repo paiml/aprender --json state,mergedAt,mergeCommit` (state MERGED) then `gh release list --repo paiml/aprender --limit 10 --json tagName,publishedAt` and `git merge-base --is-ancestor <mergeCommit> <tag>` after `git fetch upstream --tags` — the first tag containing the merge commit is the candidate; its `.sha256` asset is the pin.

Function URL recipe (plan 09-06): `just llm-endpoint-url <env> <profile>` → `URL OK (401 without key verified)`; the URL is in `deploy/llm-endpoint/.ids/url.json` (`url` key). Curl checks: `curl -s -o /dev/null -w '%{http_code}' -X POST -H 'content-type: application/json' [-H "authorization: Bearer $APR_PROBE_KEY"] --data '{"model":"x","messages":[{"role":"user","content":"Hi"}],"max_tokens":1}' "$URL/v1/chat/completions"`.
Probe over HTTPS: `just llm-endpoint-probe "$URL/v1" Qwen3.5-0.8B-Q4_K_M deployed-https "<entry apr line>"` with `APR_PIN_PROFILE=fixed` → `conformance-<APR_TAG>-deployed-https.json`; the record's `base` field would contain the URL — the wrapper must redact it to `https://<function-url>/v1` before writing (add `--redact-base` to probe_openai.py if absent: the executor adds it in this plan to deploy/llm-endpoint/probe/probe_openai.py).
Agent loop over HTTPS (plan 09-05): `cargo build --release --manifest-path deploy/llm-endpoint/probe/agent-loop/Cargo.branch.toml` then the binary with `--base "$URL/v1" --model Qwen3.5-0.8B-Q4_K_M --insecure-http false --max-tokens 384 --timeout-s 300 --out <scratch>/agent-run-deployed-https.json`; `OpenAiCompatSource` requires HTTPS off-loopback unless allow_insecure_http (openai_compat.rs:86).
Timeouts of record: platform 120 s (`LLM_HTTP_TIMEOUT_SECS`), SDK default 60 s (the driver raises it); the warm two-tool turn measured in 09-07 (`derived.two_tool_turn_s`) — pre-warm with `just llm-endpoint-warm` right before each run.
