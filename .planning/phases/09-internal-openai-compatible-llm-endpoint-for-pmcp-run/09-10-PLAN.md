<objective>
The proof the phase is named for (SC1): a pmcp.run agent selects the internal endpoint by
configuration alone and completes a real two-tool turn through the platform's own `openai_v1`
client — then switches back by configuration. The rows and the secret are created by the team or
the owner after the review (D-11); Claude pre-warms, collects both sides' evidence, and closes the
live record. The acceptance of the turn is a script with its own refusal case table, not a one-line
assertion: it requires both distinct tools, the tool-call wire properties, an accepted tool result,
derived timing and request-id-correlated endpoint evidence.

Purpose: SC1 is the user's stated goal ("implement the end-to-end including the pmcp.run parts");
everything before this plan exists to make this turn a configuration change.
Output: the verifier, the platform-turn evidence, the completed live record (`outcome:
deployed-passed-e2e`), the brief's status updated with the run id.
</objective>

Telemetry the platform emits per LLM call (iteration.rs:42-61 comment): `tracing::info!(... "llm-call-latency")` with `latency_ms`, `provider_id`, `model_id` — CloudWatch Logs Insights: `filter @message like /llm-call-latency/ | stats pct(latency_ms, 50) by provider_id, model_id`. The platform also logs the resolved endpoint on each call (llm/service.rs `call_provider`) — the T-09-50 exposure.
Endpoint side: the function's log group `/aws/lambda/aprender-llm-endpoint-<env>` — `REPORT RequestId: <uuid> Duration: … Billed Duration: … Max Memory Used: … [Init Duration: …]` lines and `[entry]` lines. Correlate by Lambda RequestId inside an isolated window (reserved concurrency 1 serialises invocations).
Platform timeout 120 s per attempt, two Class-1 attempts (iteration.rs:62-72); `AgentConfig.maxTokens` default 4096 → must be 256-512 for the demo.
Pre-warm: `just llm-endpoint-warm <env> <profile>` (plan 09-06) — one authenticated 1-token invoke.
Read-only verification of the row (if the executor has an AWS profile for the pmcp.run account): `aws dynamodb get-item --table-name <LLMProvider table> --key '{"id":{"S":"aprender-internal"}}'`; otherwise the team/owner pastes the row JSON (secretKeyName only). The LLMProvider table name is read from the durable-agent Lambda's `LLM_PROVIDERS_TABLE` environment variable (agent.ts:214-216).
Our PR set (plans 09-09, 09-12): pmcp-run changes only amplify/data/resource.ts, config/loader.rs, handler/iteration.rs; the SDK changes only pmcp-agent's openai_compat.rs — neither touches `src/llm/transformers/`.
